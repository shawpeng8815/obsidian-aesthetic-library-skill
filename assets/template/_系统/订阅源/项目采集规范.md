# 项目采集规范

## 目标

为全部设计工作室建立可累积、可追溯的官方项目基线，用于判断每周真正新增的项目。机器基线与 Obsidian 公开内容卡分开。

## 有效项目

一个条目进入正式项目基线，需要同时满足：

1. 来自工作室官网、官方 API、官方 Feed 或官网明确指向的官方作品频道。
2. 属于独立设计项目或案例，可以确认工作室参与。
3. 具有稳定的项目 URL 或官方项目 ID。
4. 至少可以获取项目标题；官网没有日期时允许留空。

排除招聘、活动、采访、获奖新闻、服务页、类别筛选页、隐私条款、重复发布及单纯转载。

## 时间字段

- `source_published_at`：官网明确标注的发布时间。
- `project_year`：能够确认时记录项目实际完成年份。
- `first_seen_at`：系统第一次发现的时间。
- `last_seen_at`：最近一次成功采集中仍然可见的时间。

`source_published_at` 为空时，同步顺序使用 `first_seen_at`，不将它宣称为官方发布时间。

## 数据分层

- `project`：通过该工作室的项目识别规则，进入正式基线。
- `review`：采集到了候选链接或媒体资产，当前规则不能将它确认为独立项目。
- `excluded`：可以确认是栏目、类别或其他非项目页面。

## 每周同步

1. 重新采集全部工作室。
2. 对 URL 做标准化，与永久项目账本比较。
3. 首次出现且被判定为 `project` 的条目进入本周编辑候选。
4. 新 URL 只追加，旧 URL 不会因官网下架、翻页或采集数量变少而删除。
5. 单站结果较上一次成功采集骤降时，本次标记异常并不更新该站账本。
6. 对 `watch_only` 来源，新链接或新媒体只进入变更提醒，不直接当作项目。

## 发布边界

基线和每周新增首先进入机器账本。只有完成编辑判断并确认发布的项目，才生成 Obsidian 内容卡。
