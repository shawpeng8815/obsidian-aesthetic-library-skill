# Collection and editorial workflow

Read this file when establishing a baseline, processing weekly candidates, writing content cards, or preparing a featured issue.

## Two update types

- Baseline backfill: record already-published official projects in the permanent ledger without sending them to the public gallery.
- Weekly sync: compare all current official sources with the ledger and emit only first-seen verified projects as candidates.

Never delete historical ledger entries because a site removes a page or a crawl returns fewer items.

## Separation of responsibilities

1. Collection identifies stable official project units and deduplicates URLs.
2. AI editing verifies the candidate, reads the project, tags it, and drafts a concise observation.
3. Human editing decides whether it enters the gallery or a featured issue.

Weekly synchronization must not publish cards automatically.

## Selection dimensions

Use four editorial dimensions as prompts for judgment, not a mechanical total score:

- Visual difference: the work has a recognizable visual position relative to routine work in the same category.
- System completeness: the core idea maintains meaningful relationships across relevant touchpoints.
- Media expansion: typography, image, motion, space, material, or interaction materially develops the idea.
- Context relation: visual choices connect coherently with the brand, cultural setting, public issue, or use situation.

Write a concrete reason tied to visible project evidence. Avoid generic praise, invented design intentions, and claims that every project represents a universal method.

## Issue limits

- Issue 01 may contain up to 15 projects.
- Issue 02 onward may contain up to 10 projects.
- No minimum is required.

Keep official introduction text. When it is not Chinese, append the Chinese translation in the same paragraph without a translation heading, HTML comment, or extra label.
